# 디자인 시안 요구사항

- 작성일: 2026-10-26
- 대상: `src1`, `src2`, `src3` 시안을 만드는 작업자
- 함께 읽을 문서: `가계부-시나리오-수업-기획서.md` (1, 2, 4, 5, 6.1, 6.2, 6.4장), `docs/core-api.md`
- **상태: 완료된 비교 단계의 기록입니다.** 세 시안 제작·비교를 마치고 src1(통장 정리)을 채택했고, 그 시안이 지금의 `src/` 앱입니다. 본문의 `srcN` 표기는 당시 세 시안을 가리킵니다.

## 1. 목적

같은 데이터와 같은 목업 상태로 화면 디자인 시안 3개를 만들어 비교한 뒤 하나를 고릅니다. 시안은 템플릿 수준입니다.

- 6개 화면을 목업 스냅숏(`FIXTURES`)으로 그려서 생김새, 정보 구조, 상호작용 방향을 보여 줍니다.
- 시뮬레이션 엔진(`step`)은 구현하지 않습니다. 버튼은 그럴듯한 다음 스냅숏으로 이동하면 충분합니다.
- 고른 시안의 컴포넌트를 실제 앱의 출발점으로 씁니다. 그래서 컴포넌트 구조가 깔끔해야 합니다.

## 2. 제품 맥락

| 항목 | 내용 |
| --- | --- |
| 사용자 | 고등학생. 40분 수업 안에서 각자 접속해 혼자 진행하고, 끝에 몇 명이 발표 |
| 기기 | 노트북과 태블릿이 대부분, 휴대폰은 소수. 발표는 교실 프로젝터 |
| 수업 목표 | 목적별 계좌로 돈을 나누는 가계부를 짜고, 12개월 동안 돌발 상황마다 어느 돈을 어떻게 쓸지 판단 |
| 게임성 | 로그라이크 게임처럼 선택이 상태로 남아 다음 장면과 다음 달을 바꿈. 도박수를 던진 뒤 대응을 다시 고름 |
| 감정 흐름 | 첫 월급의 설렘 → 계획 → 돌발 상황의 긴장 → 결과 체감 → 결산의 성취와 반성 |
| 톤 | 고등학생이 "게임 같다"고 느끼되 유치하지 않게. 숫자는 금융 앱처럼 정확하고 빨리 읽혀야 함 |

## 3. 공통 제약 (세 시안 모두)

### 3.1 기술

- 이미 설정된 Vite + React 19 + TypeScript + Tailwind CSS v4를 씁니다.
- 추가 패키지는 자기 시안 폴더에만 설치합니다: `pnpm --filter @gagyebu/srcN add <패키지>`.
    - 허용: 애니메이션(`motion` 등), 아이콘(`lucide-react` 등), 폰트(`@fontsource/*`, `pretendard` 등), headless 컴포넌트.
    - 금지: 무거운 UI 키트(MUI, Chakra, Ant Design), 차트 라이브러리 (순자산 그래프는 SVG로 직접), 외부 CDN.
- 폰트와 이미지는 모두 번들에 포함합니다. Google Fonts 링크 같은 외부 요청은 쓰지 않습니다 (교실 네트워크가 막혀 있을 수 있음).
- 아이콘이나 일러스트가 필요하면 SVG로 직접 그리거나 아이콘 패키지를 씁니다. 이모지를 아이콘 대신 쓰지 않습니다.

### 3.2 작업 범위

- 자기 폴더(`srcN/`)만 고칩니다. `packages/`, `docs/`, 기획서, 다른 시안 폴더, 루트 설정은 고치지 않습니다.
- `packages/draft-kit`의 셸과 네비게이터는 디자인 대상이 아닙니다.
- core의 데이터나 타입이 부족하면 고치지 말고 `srcN/DESIGN.md`의 "core에 대한 제안"에 적습니다.
- git 커밋은 하지 않습니다. 작업이 끝나면 총괄이 커밋합니다.

### 3.3 데이터와 계산

- 화면에 나오는 문구와 숫자는 core 데이터에서 가져옵니다 (`EVENTS`, `SURVEY`, `GUIDE_CARDS`, `ACCOUNTS`, `ACHIEVEMENTS`, `ENDINGS`, `CLOSING_TIPS`, `PROMPTS` 등). 화면용 보조 문구(버튼 이름, 빈 상태 안내)는 시안에서 써도 됩니다.
- 금액 계산과 표기는 `selectors.ts`, `format.ts`의 함수를 씁니다. 숫자에는 `tabular-nums`를 씁니다.
- `step()`은 호출하지 않습니다 (예외가 남). 입력, 패널 열기, 금액 나누기는 컴포넌트 로컬 상태로 흉내 냅니다.

### 3.4 교육용 원칙

- 선택지에 정답 힌트를 주지 않습니다. 좋은 선택은 초록, 나쁜 선택은 빨강처럼 색칠하거나, 순서나 크기로 암시하지 않습니다. 선택지의 생김새는 `kind`(지불형, 무지출형, 도박형 등)에 따라서만 달라질 수 있습니다.
- 대신 사실 정보는 분명하게 보여 줍니다: 잠긴 선택지와 이유, 지불 수단 경고(적금 해지, 청약 초기화, 투자 손실 확정), 할부 총액과 개월 수, 공개 정보(`reveal`).
- 학습용 가정 금리라는 점을 시뮬레이션 화면 어딘가에 작게 표시합니다.

### 3.5 화면 크기와 접근성

| 이름 | 크기 | 우선순위 |
| --- | --- | --- |
| laptop | 1366×768 | 주 대상. 시뮬레이션의 핵심(장면 카드, 선택지, 계좌 요약)이 첫 화면에 들어오면 좋음 |
| tablet | 1024×768 | 주 대상 (가로) |
| tabletPortrait | 820×1180 | 보조 |
| phone | 390×844 | 깨지지 않을 것 |

- 한글 줄바꿈: 본문에 `word-break: keep-all`.
- 대비 4.5:1 이상, 키보드로 모든 조작 가능, 포커스 표시, 터치 대상 44px 이상.
- `prefers-reduced-motion`이면 카운트업과 큰 움직임을 줄입니다.
- 결과 화면의 발표용 크게 보기는 교실 뒤에서도 읽혀야 합니다.

## 4. 화면별 요구사항

스냅숏 목록과 각각 꼭 보여야 하는 것은 `docs/core-api.md` 7장에 있습니다. 모든 스냅숏이 오류 없이 그려져야 합니다.

### 4.1 시작 (`start-name`, `start-reveal`)

- 수업 상황 제시: "여러분은 오늘 첫 월급을 받았습니다".
- 닉네임 입력 → 월급 공개. 월급이 기준 평균소득 ±10% 안에서 정해진다는 설명.
- 월급 공개 연출 (예: 숫자 카운트업). "축하합니다! 하늘님의 첫 월급은 2,630,000원입니다".
- 다음 → 설문.

### 4.2 소비습관 설문 (`survey-q1`, `survey-q7`, `survey-result`)

- 한 화면에 질문 하나, 진행 표시(1/7), 이전으로 돌아가기.
- 결과: 소비 성향 유형, 한 줄 피드백, 조언, 추천 가계부 미리보기 (계좌별 비율).

### 4.3 재무 기초 안내 (`guide-1`, `guide-3`)

- 카드 6장을 넘겨 보는 구조와 진행 표시.
- 3번 카드(통장 쪼개기)는 계좌 6종을 한눈에 보여 주는 시각화를 포함합니다. 이 계좌 표현은 이후 가계부와 시뮬레이션에서도 일관되게 씁니다.

### 4.4 가계부 작성 (`budget-ok`, `budget-over`)

- 자동이체 5개, 지출 10개(고정비/변동비 묶음), 생활비 여유분을 수정합니다. 1만 원 단위 조정이 쉬워야 합니다. 입력 방식(슬라이더, 스테퍼, 직접 입력)은 시안이 정합니다.
- 실시간 표시: 합계, 남은 금액, 저축률, 계좌별 비율 막대.
- 합계가 월급과 같을 때만 확정 가능. 초과나 미달이면 얼마인지 알려 줌 (`budgetIssues`).
- 추천값으로 되돌리기, "AI에게 물어보기" 프롬프트 복사 버튼.
- 이 편집기는 시뮬레이션의 가계부 조정 단계에서도 다시 씁니다 (재사용 가능한 컴포넌트로).

### 4.5 12개월 시뮬레이션 (가장 중요)

항상 보이는 것

- 월 진행 1~12 (이벤트 달, 이벤트 없는 달, 12월 결산 구분), 순자산, 만족도, 신용점수, 비상금 개월 수.
- 계좌 6개의 잔고와 이번 달 변화, 남은 부채.
- 상태 효과 목록: 이름, 성격(buff/debuff/neutral), 남은 기간, `note`, 행동 버튼(운동화 팔기). 예약된 장면 예고.

단계별 화면 (`state.step`)

| 단계 | 스냅숏 | 요구사항 |
| --- | --- | --- |
| payday | `sim-jan-payday` | 월급 입금 → 자동이체 → 생활비 지출 → 이자·수익 순서의 연출. 1월은 튜토리얼 안내를 덧붙임 |
| scene | `sim-feb-scene`, `sim-feb-seller`, `sim-mar-resell`, `sim-apr-check`, `sim-may-message`, `sim-jul-reveal`, `sim-aug-crash`, `sim-nov-invite`, `sim-nov-locked` | 장면 카드. 이벤트 유형·코드·제목. 채널 5종(`narration` `messenger` `sms` `news` `app`)이 서로 다르게 보여야 함. `reveal` 정보 강조. 선택지는 `kind`별 표시, 잠긴 선택지와 이유. 이벤트에 `promptId`가 있으면 AI 프롬프트 복사 |
| 지불 패널 | `sim-feb-pay` | `fundingOptions()`로 수단별 한도와 경고. 여러 계좌로 나눠 내기, 남은 금액 표시, 합계가 맞아야 확정. 카드는 일시불/할부 개월 선택과 매달 갚을 돈 |
| 입금 패널 | `sim-aug-deposit` | 받을 금액과 넣을 계좌 고르기. 급락 매도는 손실 확정 금액도 표시 |
| outcome | `sim-feb-outcome` | 피드백 문구, 변화 목록(계좌, 만족도, 신용, 상태), 이어지는 장면이나 예약 예고, 이벤트가 끝났으면 교훈 |
| adjust | `sim-jun-adjust` | 조정 이유(`budgetReason`)와 가계부 편집기. 합계를 맞춰야 진행 |
| report | `sim-oct-report` | 월말 리포트: 이번 달 수입·지출·이자, 순자산 변화, 상태 효과, 생활비 부족 경고, "다음 달" 버튼 |

### 4.6 결과 · 엔딩 (`result-balanced`, `result-debt`, `result-present`)

- 12월 결산 연출: 마지막 월급과 적금 만기(원금, 세전 이자, 세금, 세후 이자).
- 엔딩 칭호와 한 줄 문구.
- 12개월 순자산 선 그래프 (SVG 직접), 계좌별 최종 잔고.
- 처음 가계부와 최종 가계부 비교 (`settlement.budgetDiff`).
- 선택 기록 타임라인 (`decisions`).
- 도전과제: 달성, 미달성, 숨김(달성 전에는 "???"). 놓친 도전과제가 "다른 선택을 했다면"을 떠올리게 해야 함.
- 실행법과 마음가짐 요약 (`CLOSING_TIPS`).
- 발표용 크게 보기 (`ui.presentation`): 닉네임, 엔딩, 순자산 그래프, 핵심 선택 3~4개, 도전과제 수 정도만 크게.

## 5. 시안별 배정

각 시안은 아래 디자인 스킬 하나만 씁니다. 다른 시안의 스킬이나 결과를 참고하지 않습니다. 시각 방향(색, 서체, 레이아웃, 모션)은 각 스킬의 방법에 따라 스스로 정합니다.

| 시안 | 폴더 | 디자인 스킬 | 위치 | 출처 |
| --- | --- | --- | --- | --- |
| 1 | `src1/` | frontend-design (Anthropic 공식) | `design-skills/frontend-design/SKILL.md` | github.com/anthropics/claude-code `plugins/frontend-design` (커밋 2eff7a8) |
| 2 | `src2/` | UI/UX Pro Max | `design-skills/ui-ux-pro-max/SKILL.md` | github.com/nextlevelbuilder/ui-ux-pro-max-skill (커밋 1f88579) |
| 3 | `src3/` | Impeccable | `design-skills/impeccable/SKILL.md` | github.com/pbakaus/impeccable (커밋 e38dfd4) |

- 스킬 안의 스크립트를 실행할 때는 그 스킬 폴더 경로를 그대로 씁니다.
- 스킬이 만드는 문서(PRODUCT.md, DESIGN.md, 설계 노트 등)는 자기 시안 폴더 안에 둡니다. 저장소 루트에 만들지 않습니다.
- 스킬의 지침과 이 문서가 충돌하면 이 문서(특히 3장 공통 제약)를 따릅니다.

## 6. 작업 순서

1. 기획서, `docs/core-api.md`, 이 문서, 배정된 스킬의 `SKILL.md`를 읽습니다.
2. 스킬의 방법대로 방향을 정하고 `srcN/DESIGN.md`에 먼저 적습니다.
3. 디자인 토큰(색, 서체, 간격, 모션)과 공통 컴포넌트(금액 표시, 계좌 카드, 가계부 편집기, 장면 카드, 선택지)를 만든 뒤 화면을 채웁니다.
4. 확인합니다.
    - `pnpm --filter @gagyebu/srcN typecheck`, `pnpm --filter @gagyebu/srcN build`
    - `pnpm shots srcN` (laptop, tablet, phone). 오류가 나면 고칩니다.
    - 스크린숏을 직접 열어 보고 겹침, 잘림, 넘침, 읽기 어려운 대비를 고칩니다. 특히 laptop의 시뮬레이션 화면과 phone 전체를 봅니다.
5. `srcN/DESIGN.md`를 마무리합니다.
