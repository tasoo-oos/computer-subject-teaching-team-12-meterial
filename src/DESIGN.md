# 앱 디자인: 통장 정리

시안 3종 비교에서 채택된 디자인입니다. 비교 기록은 `docs/design-review.md`에 있습니다.

## 1. 방향과 콘셉트

**통장 정리.** 은행 ATM에 종이 통장을 넣으면 프린터 헤드가 "지이익" 하며 거래 내역을 한 줄씩 찍어 줍니다. 한국 사람이라면 누구나 아는 이 장면이 "내 돈이 어디로 갔는지 눈으로 확인하는 순간"입니다. 이 디자인은 화면 전체를 종이 통장의 문법으로 짓습니다. 연한 민트빛 지문(guilloche) 무늬 용지, 괘선 위에 찍힌 날짜·적요·입금·출금·잔액, 표지 색으로 구분되는 여섯 권의 통장, 은행 인주 도장. 게임의 긴장(장면 카드, 선택지, 상태 효과)은 그 통장 옆에서 벌어지는 "사건"으로 둡니다.

대담함은 한 곳에만 씁니다. **월급날 통장에 거래가 한 줄씩 인쇄되는 연출**과, 그 통장을 닮은 1월의 거래 표입니다. 나머지는 금융 앱처럼 조용하고 정확하게 둡니다. 크림색 배경, 둥근 SaaS 카드, 형광 강조색, 대문자 머리표 같은 기본값은 쓰지 않았습니다.

## 2. 토큰

### 색

| 이름 | 값 | 역할 |
| --- | --- | --- |
| 통장 용지 | `#EDF2EE` | 배경. 은행 통장 속지의 연한 회녹색 |
| 속지 흰색 | `#F9FBF9` | 카드·패널 면 |
| 잉크 남색 | `#18264A` | 본문, 주요 버튼, 괘선 위 인쇄 잉크 |
| 괘선 | `#BCCAC2` / `#D8E2DC` | 통장의 줄, 구분선 |
| 인주 빨강 | `#B8282F` | 출금 금액, 사실 경고, 도장. 선택지에는 쓰지 않음 |
| 입금 파랑 | `#1E4FA8` | 입금 금액, 완료 상태 |
| 형광 펜 | `#FBE9A9` | 이번 달 변화, 공개 정보 강조 |

계좌 6종은 통장 표지 색으로 구분하고 시작·안내·가계부·시뮬레이션·결과에서 똑같이 씁니다. 생활비 `#D9961A`(호박), 비상금 `#1F7A8C`(청록), 적금 `#3D6B35`(녹색), 투자 `#6B48B5`(보라), 목표 `#B23A63`(장미), 청약 `#8B5E34`(갈색). 표지 위 글자는 대비 4.5:1을 넘도록 흰색 또는 잉크색을 골라 씁니다.

입금은 파랑, 출금은 빨강이라는 한국 은행 앱의 관례를 따랐습니다. 이 색은 **돈의 방향**만 뜻하고 선택의 좋고 나쁨을 뜻하지 않습니다.

### 서체

- 본문·숫자: **IBM Plex Sans KR** (400/500/600/700). 은행 서식처럼 단정하고 숫자가 또렷합니다. 한국 웹의 기본값인 Pretendard·Noto Sans KR을 피했습니다. 모든 금액에 `tabular-nums`.
- 제목: **Black Han Sans**. 굵고 각진 포스터 서체로 게임 같은 긴장을 만듭니다. 화면 제목, 사건 제목, 엔딩 칭호, 통장 표지에만 씁니다.
- 크기 단계: 11 / 12 / 13 / 15 / 17 / 19 / 21 / 26 / 33 / 42 / 64px. 본문 줄 길이는 40자 안쪽, `word-break: keep-all`.
- 두 서체 모두 `@fontsource`로 번들에 넣었습니다. 외부 요청은 없습니다.

### 레이아웃

- 왼쪽 정렬이 기본, 금액만 오른쪽 정렬(통장 잔액 칸).
- 모서리는 위계에 따라 다릅니다. 통장 표지 4px, 패널 10px, 메신저 말풍선 18px. 모든 카드에 같은 둥글기를 주지 않았습니다.
- 시뮬레이션은 `본문(장면·선택) + 340px 통장 기둥`의 2단. 1366×768에서 장면·선택지·계좌 요약이 첫 화면에 들어옵니다.
- 태블릿 세로·휴대폰(1024px 미만)에서는 기둥이 **"순자산 X · 생활비 통장 잔액 ▾" 한 줄 바**로 접힌다(S7). 펼치면 같은 자리에 통장·상태·가계부 요약이 나온다. 지불 패널은 같은 폭에서 **"수단 고르기 → 금액" 2단계**로 쪼개고, 금액 단계의 합계·확정은 화면 아래 sticky 바에 둔다. 가계부 화면도 같은 폭에서 남은 금액·확정 버튼이 화면 아래에 붙는다. 노트북·태블릿 가로(1024px 이상)는 위 2단 레이아웃 그대로다.
- 지불 패널이 열리면 장면은 제목 한 줄로 접히고, 선택지 자리를 패널이 대신합니다. 맥락은 남기고 높이는 줄입니다.
- 결과는 `엔딩 + 적금 영수증` → `그래프 + 최종 잔고` → `가계부 비교 + 선택 기록 + 도전과제` → `정리` 순서의 긴 스크롤. 발표용은 화면 하나에 다 들어갑니다.

### 움직임

- 월급 공개: 숫자 카운트업 한 번(1.4초), 도장이 `stamp-in`.
- 월급날: 거래 줄이 0.38초 간격으로 `print-in`(왼쪽에서 오른쪽으로 인쇄).
- 화면 전환: `sheet-in` 220ms. 그 밖의 hover는 120ms 색 변화만.
- `prefers-reduced-motion: reduce`이면 카운트업은 최종값, 인쇄·도장은 정지 상태로 바로 표시합니다. 스크린숏 모드(`?shot`)도 같은 정지 상태를 써서 항상 완성된 화면을 찍습니다.

## 3. 화면별 핵심 아이디어

### 시작

- 첫 화면은 급여명세서 한 장. 닉네임을 넣기 전에는 실수령액이 검은 띠로 가려져 있습니다.
- 월급 공개는 "축하합니다" 아래 숫자가 올라가고, 오른쪽 명세서에 금액과 빨간 "첫 월급 지급" 도장이 찍힙니다.
- 월급이 기준 평균소득 ±10% 안에서 정해진다는 사실을 눈금 바로 보여 줍니다. 친구와 달라도 결과 차이는 선택에서 나온다는 문장을 함께 둡니다.

### 소비습관 설문

- 한 화면에 질문 하나, 위쪽에 7칸 진행 막대와 `1 / 7`. 선택지는 56px 높이의 라디오 행.
- "이 답은 식비 예산에 반영됩니다"처럼 답이 어디에 쓰이는지 먼저 알려 줍니다.
- 결과는 유형 이름을 포스터 크기로, 오른쪽에 추천 가계부 미리보기. 계좌별 비율 막대는 이후 가계부·결과에서 같은 컴포넌트를 씁니다.

### 재무 기초 안내

- 6장 카드 내비게이션. 카드마다 `n / 6`, 제목, 리드, 항목, 팁.
- 3번 카드(통장 쪼개기)는 계좌 6종을 실제 통장 표지 카드로 펼칩니다. 표지 색 + 상품 + 권장 비율 + 이율 + 꺼내 쓸 때 규칙을 한눈에. 이 표지 색 체계가 이후 모든 화면의 범례가 됩니다.

### 가계부 작성

- 자동이체 5개 → 고정비 5개 → 변동비 5개 → 생활비 여유분 순서. 각 행은 `− / 직접 입력 / +` 스테퍼로 1만 원 단위 조정. 1만 원 단위가 아닌 값(예: 626,400원)은 한 번 누르면 1만 원 눈금에 맞춰집니다.
- 오른쪽 sticky 요약: 월급, 자동이체, 생활비 입금, 고정/변동/여유분, 남은 금액(0원이면 파랑, 아니면 빨강), 저축률, 계좌별 비율 막대, 추천값 복원, AI 프롬프트 복사.
- 초과·미달·음수는 `budgetIssues`로 문장을 만들고, 0원이 아니면 "1년 시작" 버튼이 꺼집니다.
- 편집기는 시뮬레이션 6월 조정 단계에서 그대로 재사용합니다(`layout="split"`).

### 12개월 시뮬레이션

상단 띠는 항상 같습니다: 월 진행 1~12(사건 있는 달은 진한 눈금과 점, 조용한 달은 흐린 눈금, 12월은 붉은 눈금, 아래에 작은 범례), 순자산, 만족도 게이지, 신용점수와 등급, 비상금 개월 수. 오른쪽 기둥에는 통장 6권(잔고 + 이번 달 변화), 남은 부채, 상태 효과(성격·남은 기간·note·행동), 예약 장면 예고, 생활비 예산, 학습용 가정 금리 안내가 있습니다.

**월급날.** 1월은 통장 한 쪽이 펼쳐지고 `월급 입금 → 자동이체 5줄 → 생활비 입금 → 생활비 지출 → 이자·수익`이 순서대로 인쇄됩니다. 계좌 카드 숫자가 같이 올라가고, 아래에 "1월은 연습입니다" 카드가 붙습니다.

**장면 카드 채널 5종.** 같은 카드 틀을 쓰되 본문만 매체에 맞게 바꿉니다.

| 채널 | 생김새 |
| --- | --- |
| `narration` | 흰 속지 위 본문. 제목과 2~4문장 |
| `messenger` | 연한 회록 배경, 발신자 아바타·이름, 꼬리가 있는 흰 말풍선, 시각 |
| `sms` | 회청색 배경의 문자 한 통. 발신자·번호 헤더, 점선 구분 |
| `news` | 남색 속보 띠. 붉은 "경제 속보", 포스터체 헤드라인, 흰 본문 |
| `app` | 앱 알림 카드. 표지 색 아이콘, 앱 이름, 알림 본문 |

- 공개 정보(`reveal`)는 노란 띠에 큰 숫자로. "이 장면에서 확인된 숫자"라는 라벨을 붙여 사실 정보임을 분명히 합니다.
- 선택지는 데이터 순서 그대로 2×2(모바일 1열), **모두 같은 크기·같은 색**. 다른 것은 `kind` 아이콘과 "지불: 낼 통장을 고름 / 돈을 쓰지 않음 / 결과는 나중에 이어짐 / 가계부를 다시 짬" 같은 동작 설명뿐입니다. 잠긴 선택지만 사선 무늬로 죽이고 이유를 흰 상자에 적습니다. 초록·빨강으로 좋고 나쁨을 칠하지 않습니다.
- 이벤트에 `promptId`가 있으면 "AI에게 물어보기"로 지금 상황을 채운 프롬프트를 복사합니다.

**지불 패널.** `fundingOptions()`의 수단별 한도와 경고를 그대로 보여 줍니다. 계좌마다 금액을 나눠 넣고, "남은 금액" 버튼으로 빠르게 채우며, 합계가 맞아야 확정됩니다. 카드는 일시불·3개월 같은 `cardMonths` 선택과 **매달 갚을 돈·수수료**를 함께 보여 줍니다. 적금·청약·투자는 "해지/초기화/손실 확정" 경고를 붙입니다. 고정 지불형은 확인 패널에서 총액과 매달 납입금을 보여 주고 확정합니다. 조정 가능한 금액(8월 추가 매수)은 스테퍼로 범위 안에서 고릅니다.

**입금 패널.** 받을 금액, 넣을 계좌 하나, 넣은 뒤 잔고를 보여 줍니다. 8월 전부 매도는 "지금 팔면 손실 123,493원이 확정됩니다. 원금은 1,040,000원입니다"를 빨간 상자로 먼저 알려 줍니다.

**결과 피드백.** 선택의 결과를 남색 카드로 크게. 왼쪽에 달라진 것(계좌·만족도·신용·부채·상태·예산), 오른쪽에 이다음(같은 달 장면 / 예약 / 끝), 가계부 조정 이유, 교훈 한 줄.

**가계부 조정.** 조정 이유를 먼저 읽히게 두고, 한 줄 요약(월급·자동이체·생활비·저축률·남은 금액) 아래에서 편집기를 두 단으로 폅니다. 합계가 맞아야 "조정 완료"가 열립니다.

**월말 리포트.** 이번 달 월급·생활비 지출·이자·투자 수익·지난달 대비 순자산, 생활비 부족 경고, 통장별 변화, 다음 달 버튼. 조용한 달에도 돈이 쌓이는 것이 보이도록 순자산 변화를 크게 둡니다.

### 결과 · 엔딩

- 왼쪽에 엔딩 칭호(포스터체 56px), 한 줄 문구, 12월 말 순자산, 월급 배수, 만족도·신용, 부채 경고. 오른쪽에 적금 만기 영수증(원금·세전 이자·세금·세후 이자, 도장)과 12월 마지막 정산.
- 12개월 순자산은 SVG 선 그래프 하나로 직접 그립니다. 축은 만 원 단위, 마지막 값은 흰 테두리를 준 라벨로.
- 통장별 최종 잔고는 표지 색 띠와 구성비.
- 처음/12월 가계부 비교는 항목·처음·12월·차이 4열. 선택 기록은 월별 세로 타임라인으로 지불 내역까지.
- 도전과제 13개: 달성(파란 체크), 미달(빈 원 + "놓친 도전과제"), 숨김은 달성 전까지 사선 카드에 "???"와 해당 월 힌트. 놓친 개수를 문장으로 세어 "다른 선택을 했다면" 대화를 유도합니다.
- 발표용은 닉네임, 엔딩, 최종 순자산, 순자산 그래프, 2·6·8·11월 핵심 선택 4개, 도전과제 수만 남깁니다. 1366 프로젝터에서 한 화면에 들어가고, 1024 태블릿에서도 깨지지 않습니다.

## 4. 스킬을 어떻게 썼는지

`design-skills/frontend-design/SKILL.md`만 읽었습니다(다른 스킬 폴더는 열지 않음). 스킬의 두 번 작업 방식을 따랐습니다.

1. **계획 먼저.** 색 6개, 서체 2개, 시뮬레이션 2단 레이아웃의 ASCII 와이어프레임, 원칙 4개를 먼저 적고 코드를 쓰기 시작했습니다.
2. **계획 비판.** 첫 안은 "흰 배경 + 둥근 카드 그리드 + 파란 강조"의 핀테크 대시보드였습니다. 같은 요구에 누구나 도달하는 기본값이라 버렸습니다. 크림색 배경도 생성형 디자인의 전형이라 통장 속지의 회녹색으로 바꿨습니다. 작은 숫자 라벨에 고정폭 서체를 쓰는 습관, 제목 위 영문 대문자 머리표, 가운뎃점 메타 문자열, 버튼 끝 화살표도 걷어냈습니다. 번호는 실제 순서가 있는 곳(수업 6단계, 설문 1/7, 안내 n/6, 월 1~12, 월급날 처리 순서, 선택 기록)에만 남겼습니다.
3. **주제에서 출발.** "가계부"의 실제 재료는 통장·거래 내역·도장·표지 색입니다. 장식이 아니라 정보 구조로 썼습니다. 계좌 색은 목적을 외우게 하고, 거래 표는 입금·출금 방향을 즉시 읽게 합니다.
4. **절제.** 화려한 것은 월급날 인쇄 연출 하나. 나머지는 여백과 괘선, 두 서체의 대비로만 만듭니다. 이모지는 쓰지 않고 아이콘은 `lucide-react` SVG만 씁니다.
5. **스스로 비판.** 스크린숏을 직접 열어 보고 고친 것: 계좌 범례 겹침(6열 → 줄바꿈), 적금 도장이 금액을 덮음(절대 배치 → 흐름 배치), 순자산 축 라벨 잘림(축 포맷·여백), 전화에서 헤더 단계가 "1 2 3 …"으로 뭉개짐(모바일은 n단계 + 막대), 지불 패널이 화면을 넘김(2열·장면 접기·행 압축), 10월 리포트의 "지난달 대비"가 두 달 전과 비교되던 문제(마지막 기록 기준), 뉴스 채널 제목 중복, 선택지 잠금 대비, 결과 화면의 빈 열(도전과제를 왼쪽 열로 옮김), SVG 라벨 크기.

실행한 명령:

```
pnpm --filter @gagyebu/app add @fontsource/ibm-plex-sans-kr @fontsource/black-han-sans lucide-react
pnpm --filter @gagyebu/app typecheck
pnpm --filter @gagyebu/app exec vite build
pnpm shots
pnpm shots --viewports=tabletPortrait
```

스킬 폴더에는 `SKILL.md`와 `LICENSE.md`만 있어 실행할 스크립트는 없었습니다.

## 5. 교육용 원칙을 지키는 방법

- 선택지의 생김새는 `kind`로만 달라집니다. 색·크기·순서로 정답을 암시하지 않습니다. 데이터 순서를 그대로 씁니다.
- 사실 정보는 오히려 크게: 잠긴 이유, 지불 수단 경고(적금 해지·청약 초기화·투자 손실 확정), 할부 총액과 개월 수, `reveal` 숫자.
- "학습용 가정 금리"는 시뮬레이션 기둥과 결과 하단에 작게 상시 표시합니다.
- 키보드: 모든 조작이 `button`/`input`/`label`, `:focus-visible` 3px 파랑 테두리. 터치 대상은 44px 이상(스테퍼 ±, 지불 패널 버튼 포함).
- `prefers-reduced-motion`에서 카운트업·인쇄·도장을 정지.

## 6. 남은 문제와 실제 앱으로 옮길 때 할 일

- **엔진 연결.** 지금은 지불 계획·입금 계좌·가계부 수정이 컴포넌트 로컬 상태입니다. `step()`이 생기면 `choose { payment }`, `choose { depositTo }`, `setBudget`, `statusAction`으로 바꿔야 합니다. 화면 뼈대는 그대로 두고 콜백만 연결할 수 있게 했습니다.
- **월별 계좌 변화.** `state.payday`와 이번 달 `decisions`를 합성해 보여 줍니다(`lib/month.ts`). 실제 앱에서는 엔진이 남기는 월별 원장을 쓰는 게 정확합니다.
- **이동표.** `components/sim/routes.ts`가 스냅숏 id를 직접 가리킵니다. 실제 앱에서는 `step`의 결과(다음 장면/예약/리포트)로 대체해야 합니다.
- **발표용.** 지금은 `result-present` 스냅숏과 닫기 버튼뿐입니다. 실제로는 Fullscreen API, Esc 종료, 글자 크기 단계가 필요합니다.
- **전화 지불 패널 — 해결됨(S7).** 7개 수단이 1열로 쌓여 길어지던 문제는 "수단 고르기 → 금액" 2단계로 나눠 해결했습니다. 1024px 미만에서만 2단계로 동작하고, 금액 단계의 합계·확정은 화면 아래 sticky 바에 둡니다. 노트북·태블릿 가로는 한 패널 레이아웃 그대로입니다.
- **안내 카드 1·2·4·5·6**은 텍스트만 있습니다. 3번처럼 카드별 도해를 넣으면 좋지만, 이번 범위에서는 정보 위계를 먼저 맞췄습니다.
- **월 진행 띠**는 사건/조용한 달을 눈금 밝기와 점으로 구분합니다. 색각 이상 사용자를 위해 범례를 넣을지 다음 단계에서 검토해야 합니다.
- **숫자 표기.** 화면 곳곳에서 `formatMan`(만 원)을 씁니다. 정확한 원 단위가 필요한 곳(가계부 편집, 지불 패널, 결과 잔고)은 `formatWon`을 씁니다. 기준을 문서화하면 좋겠습니다.

## 7. core에 대한 제안

1. **할부 계산 선택자.** `fixtures.ts`의 `cardDebt`와 같은 월 납입금·총액·수수료 계산이 화면에도 필요합니다. `cardInstallment(amount, months, interestFree)`를 `selectors.ts`에 내보내 주세요. 지금은 `lib/accounts.ts`에 같은 식을 복제했습니다.
2. **계좌별 월 변화.** `payday` + `decisions`를 화면이 합성하지 않도록 `accountDeltas(state)`를 주세요.
3. **목업의 `scheduled` 비어 있음.** `sim-feb-scene`(D 선택 시 4월 재등장), `sim-mar-resell`(4·6월 시세) 같은 스냅숏에 예약 장면이 없어 "예약된 장면 예고"를 실제 데이터로 보여 줄 수 없습니다. 픽스처에 `scheduled`를 채워 주세요.
4. **지불 계획 검증.** `PaymentPlan`의 합계 일치, 카드 개월, 계좌 한도를 검사하는 `validatePayment(state, pay, plan)`이 있으면 패널과 엔진이 같은 규칙을 씁니다.
5. **`budgetIssues`의 음수 항목 라벨.** `negative`가 키만 주므로 화면이 `EXPENSES`/`ACCOUNTS`를 다시 조회합니다. `label`을 함께 주거나 `issueText(issue)`를 core에 두면 좋겠습니다.
6. **결산 근거.** `Settlement`에 엔딩 판정에 쓴 값(순자산 배수, 만족도, 비상금 개월)과 `budgetEdits`를 넣으면 결과 화면이 `state`를 다시 뒤지지 않아도 됩니다.
7. **축 눈금용 짧은 금액 표기.** `formatMan`은 "1,177.2만 원"이라 그래프 축에 길고 잘립니다. `formatManShort`(원 없이, 정수) 같은 보조 포맷이 있으면 좋습니다.
8. **이벤트 유형의 화면용 설명.** `EVENT_TYPE_LABEL`은 있지만 채널 라벨(`messenger` → "메신저")은 화면마다 중복 정의됩니다. core 데이터로 올릴 만합니다.
